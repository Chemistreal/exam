## 1. 지금 어긋나 있는 것 — 일곱

고치면 바로 값이 되는 것부터. 순서는 급한 순이다.

### ① KMChC 의 화면 검수 자가 **아무것도 못 막는다**

```
$ python3 tools/audit_pages.py --check ; echo $?
0                      ← 결함이 있어도 0 이다. 종료 코드가 아예 없다.
```

세 가지가 한꺼번에 어긋나 있다.

- `tools/audit_pages.py` 가 **200줄짜리 옛 판**이다(exam 259 · DT/study64 270).
  `--check` 를 읽는 자리도, `sys.exit` 도 없다
- 그래서 `--check` 를 줘도 0 을 돌려준다
- CI(`engine-sync.yml`)도 **`--check` 없이** 부른다

> DT 에서 여섯 달 동안 152장이 걸린 채 초록불이었던 것과 **똑같은 모양**이다
> (`docs/내용-400턴.md`). 그때 남긴 문장이 그대로 들어맞는다 —
> **재는 것과 막는 것은 다르다.**

지금은 7장이 다 깨끗해서 숨기고 있는 것이 없다. **다음 한 장이 문제다.**

### ② exam 의 화면 검수 자가 **열한 번째 거짓말 고침을 못 받았다**

같은 자를 네 앱이 나눠 쓰는데 판이 셋으로 갈라져 있다.

| | 줄 수 | 열한 번째 고침(같은 이름의 색을 다 모으기) |
|---|---|---|
| study64-report | 270 | ✔ 들어 있다 (**커밋된 곳은 여기 하나뿐이었다**) |
| DT | 270 | ⚠ 고쳐는 놓고 **커밋을 안 했다** — 작업본에만 있었다 |
| **exam** | 259 | ✗ 아직 `vs = dict(VAR.findall(s))` 다 |
| KMChC | 200 | ✗ (①번과 같은 옛 판) |

`dict()` 로 모으면 **같은 이름의 값이 하나만 남아** 밝은 판과 어두운 판을 함께
가진 화면에서 한쪽 팔레트가 통째로 사라진다. study64-report `english.html` 이
그래서 1.00:1 로 잡혔던 자리다.

exam 의 258장을 새 판으로 돌려 봤다 — **지금은 0장이 걸린다.** 즉 숨기고 있는
결함은 없고, **exam 이 두 벌 옷을 입은 화면을 하나라도 만들면 그때부터 못 본다.**

> `README.md` 는 "자는 exam·DT 저장소와 **같은 판**을 쓴다 — 갈라지면 한쪽만
> 고쳐진다" 고 적어 두었다. 갈라졌다.

## 4. 네 앱이 **아무도 안 재는 것**

자가 하나도 없는 자리다. 있으면 좋겠다는 뜻이 아니라, **없다는 것을 적어 두는
것**이 이 표의 목적이다.

| 무엇 | 왜 아무도 안 재나 |
|---|---|
| 화면이 실제로 **몇 초에** 뜨는가 | exam 만 첫 그림을 막는 글꼴을 본다. 나머지 셋은 1MB 짜리 화면을 그냥 둔다 |
| **휴대폰 폭**에서 무너지는가 | viewport 태그가 있는지만 본다. 360px 에서 표가 넘치는지는 안 본다 |
| 앱스크립트 창구가 **죽었을 때** | exam·DT 는 검사가 있다. study64·KMChC 는 없다 |
| 같은 학생이 **두 앱에서 다른 이름** | 네 앱이 같은 학생을 다루는데 이름·반 표기를 맞춰 보는 자가 없다 |
| 저장소가 **배포 한도**에 얼마나 가까운가 | study64 158MB · DT 283MB. Pages 한도는 1GB 다 |

## 6. 고친 것 (2026-08-10, 같은 날)

### 내가 잘못 잰 것 둘 — 먼저 적는다

**③ 을 잘못 쟀다.** "안 돌아도 0 을 돌려준다" 고 적었는데 **틀렸다.**
`prism_regression.js` 는 jsdom 이 없으면 제대로 `exit 2` 를 낸다. 내가 그 값을
`node … | tail -6` 뒤에서 읽는 바람에 파이프 끝의 `tail` 종료 코드를 본 것이다.
**자가 아니라 내가 거짓말했다.**

### 열세 번째 거짓말 — `store_ledger` 가 배지 이름을 저장 칸으로 셌다

래퍼(`X.set(KEY,…)`)를 풀려고 파일 안의 모든 `.set(…)` 호출을 훑은 탓이다.

    exam/index.html
      const map=[['전 문항','check'],['상위','starb'],…]
      …  const key = 'starb';  …  x.set(key)

저장 칸 이름은 네 저장소에서 **대문자 상수**로 둔다(`KEY`·`ROSTER_PREFIX`·
`PAL_KEY`·`DHLOG`…). 래퍼를 풀 때는 그것만 본다. 네 저장소로 견줘 보니 이
규칙으로 빠지는 것은 `starb` 하나뿐이고 나머지는 그대로 남는다.

고치기만 하면 다음에 또 넓어진다. `keys_in()` 을 떼어 내고 `lie_check` 에
참·거짓 예시 넷을 붙였다. **막는지 확인했다** — 규칙을 일부러 `^\w+$` 로
넓혀 보니 걸리고 종료 코드 1 을 냈다.

### 재는 것과 막는 것은 다르다 — 셋 다 확인했다

| 자 | 어떻게 확인했나 |
|---|---|
| `page_doors` | 빈 장 `_문없는장.html` 을 하나 넣어 보니 잡고 1 을 냈다. 치우니 0 |
| `lie_check` | `store_ledger` 규칙을 넓혀 보니 그 예시에서 걸렸다 |
| `msg_ledger` | 기준을 두 배로 올려 보니 "문장이 9,620 → 4,810 로 줄었다" 로 1 을 냈다 |

### 곁들여 나온 것 — `page_doors` 가 2분이 넘게 걸리고 있었다

자기 자신을 빼고 세려고 **화면마다 저장소를 통째로 다시 읽었다.** DT 145장에서는

검사가 느리면 사람이 안 돌린다. 한 번 읽어 표를 만들게 바꿔 네 저장소 다
**0.2~0.5초**. 판정 결과는 그대로다.
