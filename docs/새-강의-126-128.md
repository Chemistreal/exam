# 새 강의 126–128 더하기

125강 뒤에 **빈 주제를 메우는 강의**를 더한다. 126(오비탈의 마디)을 이 순서로 넣었다.
127·128도 똑같이 하면 된다. 번호는 뒤에 붙지만 내용은 앞 영역에 속한다(126 → 01 원자모형).

⚠ **명령마다 같은 줄에서 `cd` 한다.** 셸의 현재 폴더는 명령 사이에 풀린다.
`cd /home/user/dt; …` 가 아니라 `cd /home/user/dt && …` 로 — `cd` 가 실패하면 뒤가
엉뚱한 저장소에 파일을 쓴다(126 때 실제로 한 번 그랬다).

## 1. 강의 파일 — `lec-127-<영문-이름>.html`

- **뼈대는 `lec-126-orbital-nodes.html` 을 복사**해서 쓴다. `<head>`(CSS · `ct-theme` 조각 ·
  인쇄 CSS)와 맨 끝 `<script data-lec-back>` 은 그대로 두고 제목·머리·본문만 바꾼다.
  - `<title>제목 · 개념강의</title>`, `<h1 class="serif">제목</h1>`,
    `<div class="sub">127 · 영역<span class="rt">…</span></div>`, `<footer>… 127 · 제목</footer>`
- 첫 칸: `<div class="hw">이번 진단에서 <b>DT 오개념 이름</b>가 보강으로 잡혔어. …</div>` → `<p class="lead">`.
- 절 4–6개: `<div class="sec" id="s01"><div class="sec__h"><span class="sec__no">01</span><span class="sec__t">…</span></div>`.
  마지막 절은 「한 장 정리와 다음 연결」 + `<div class="big">"들고 갈 한 문장"</div>`.
- 상자: `.key`(핵심), `.trap`(함정, **하나 이상 필수**), `.eg`(예제, **하나 이상 필수**), 표, 그림(`.shape`/`.fig` + 인라인 SVG).
- 숙제: `<div class="hw"><b>직접 해보기 (숙제)</b><br>… 그리고 입으로 말해. "…" 한 바퀴 돌리면 이 개념은 네 거다.</div>` — 마지막 절 **안**에.
- 말투: 반말로 학생에게(«~해», «~야»). 실명 금지.
- 길이: 확인 문제까지 넣은 뒤 본문 글자 4,000–5,500(기존 중앙 4,389). 확인 문제가 2,000자쯤이라 **직접 쓰는 글은 3,000–3,500자**.
  (126: 5,446 · 확인 문제 빼면 3,418 · 읽는 데 약 11분)
- 자(tool)가 잡는 것:
  - 앞 번호 강의를 «다음 강 · 에서 볼 · 에서 배울» 로 부르지 않는다(`lec_audit.py` 앞뒤). 127 은 모든 강의보다 뒤다 — «005강(…)» 처럼 이름만 부른다.
  - `c = 3` · `h = …` · `R = …` · `F = …` 꼴을 쓰지 않는다(`lec_content.py` 상수 검사). 화학식은 아래첨자로(H₂O).

## 3. 개념표 24장(`const N={'001':{…}`)

개념 코드 = 강의 번호다. `concept_table.py`(24장이 같은 코드를 든다)와 `mis_sync.py`(강의 파일마다
`misconception-catalog.html` 에 줄이 있다)가 새 강의를 빠뜨리면 빨간불을 켠다.
각 장에서 **`'126'` 이 있는 표마다** 같은 꼴로 `'127'` 칸을 더한다.

| 꼴 | 넣을 값 |
|---|---|
| `N` `{l,a[,f][,p]}` | 제목 · 영역(기존 영역 이름 그대로) · 파일 · 선수(`p:['0NN']`) |
| `E`·`HP`·`REQ` `["…"]` | 선수 강의 번호 |
| `LEC` `"lec-….html"` | 파일 |
| content-rigor 갈래 | `표준개념/모형한계/정의범위/단위부호/적용조건/종합` 중 하나 |
| `{belief,correct}` · `{b,cr}` · `{b,c,t}` · `[{b,c,t,r}]` · `[['b','c','t','r']]` | 대표 오개념 · 바른 개념 · 유형(`overgen` 등 TYPES) · 뿌리 강의 |
| `{conflict,anchor,elab,verify}` · `{simp,rig,cond,err,oly}` · `{d,fo,u,e,df}` | 그 개념의 설명 |

126 은 작은 스크립트로 `'125'` 칸 뒤에 한꺼번에 넣었다(값의 첫 글자로 꼴을 가려 넣었다).
127 은 `'126'` 칸을 찾아 그 뒤에 넣으면 된다. 넣은 뒤 `tests/page-health.js` 로 304장이 오류 없이 열리는지 본다.

## 4. 생성·점검 명령 (exam)

```sh
cd /home/user/exam && python3 tools/lecture_quiz.py        # 확인 문제(한 번 더 돌려 --check 가 조용한지 본다)
cd /home/user/exam && python3 tools/lec_readtime.py --write && python3 tools/lec_anchor.py --write
cd /home/user/exam && python3 tools/gen_sw_version.py && python3 tools/gen_tool_index.py --write

cd /home/user/exam && git status -- exams.json             # 깨끗해야 한다(아니면 git checkout -- exams.json)
```

`--check` 를 안 받는 자 16개(dh_merge · dh_validate · dh_dupe_scan · dh_manifest · dh_rebalance · dh_review ·
gen_cohort_baseline · regen_seed_cohort · hwpx_exam · hwp_text · ingest_source_paper · msg_extract ·
build_wrongbook_assets · regrade_kch1to3b_q11 · review_queue · unit_unify)는 원래 FAIL 이다. 새 FAIL 이 없어야 한다.
`gen_sw_version`(final.html 을 고치면)과 `gen_tool_index`(자의 설명을 고치면)는 위 명령으로 다시 쓰면 통과한다. 브라우저 시험은 `python3 -m http.server 8931` 을 띄우고:
