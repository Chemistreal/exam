# 200턴 순차 개선안 — 네 앱 전부

> 대상: **exam**(파이널·통합 셸) · **DT** · **KMChC** · **minimalism**
> 축: **내용 · 디자인 · 교육 · 행동경제학 · 가독성**
> 이 문서는 읽는 글이 아니라 **체크리스트**다. 한 칸을 끝낼 때마다 표시하고,
> 잰 숫자를 그 자리에 적는다.

---

## 이 문서가 있는 이유

지난 작업에서 실제로 고쳐진 것은 **전부 재고 나서** 나왔다.

- 통합 셸의 흐린 글씨 `--muted` 3.52:1 (눈으로는 "좀 흐린가?")
- DT 해설지 127장에 `viewport` 없음 → 휴대폰에서 글씨가 **5.5px 로 보이고 있었다**
- DT 주기율표 원자량 **6.3px** — 시험 중에 보라고 만든 표다
- 재시가 학생이 틀린 개념의 **55.9%만** 묻고 있었다

넷 다 눈으로는 안 보였다. 그리고 넷 다, 재는 자를 만들자마자 30분 안에 나왔다.

### 원칙 넷

1. **재고 고친다.** 의견으로 고치면 다음 사람이 도로 되돌린다.
2. **잰 값은 검사로 박는다.** 안 박으면 6개월 뒤 원위치다.
3. **자가 거짓말을 하면 즉시 멈추고 자부터 고친다.** 잘못 재는 자는 안 재느니만
   못하다 — 사람이 경고를 무시하게 되고, 그러면 진짜가 와도 안 본다.
   (이 자는 이미 세 번 거짓말을 했다: `esc()` 쓴 자리를 잡음 / 문장 뒤쪽의 엉뚱한
   `.name` 을 잡음 / 어두운 화면에서 흰 글씨를 흰 바탕에 얹어 잼)
4. **화학 내용의 옳고 그름은 기계가 판단하지 않는다.** 그건 선생님이 본다.
   기계는 *사람이 판단할 필요가 없는 것*만 본다.

# 1부 — 재는 자를 넓힌다 (1~30턴)

지금 자는 **글자·색·뼈대**만 본다. 사람이 판단할 필요 없는 것 중 아직 안 재는 것들.

### 1회차 (1~10턴) · 가독성 · 전 저장소
- [ ] **키보드로 끝까지 갈 수 있나** — 탭 순서, 포커스 링이 보이나, 갇히는 자리(모달)
      *재는 법:* playwright 로 Tab 을 50번 눌러 `document.activeElement` 경로를 찍는다.
      *끝난 기준:* 모든 조작 자리에 포커스 링이 보이고, 모달에서 Tab 이 안 빠져나간다.
- [ ] **낭독기가 읽을 수 있나** — 이름 없는 단추, 표 헤더(`<th scope>`), 폼 라벨
      *잰 값 있음:* hub 1곳. 나머지 화면은 아직 안 쟀다.
- [ ] **색만으로 말하는 자리** — 통과/미달을 색으로만 표시하면 색맹은 못 읽는다
      *재는 법:* 색상 필터를 씌우고 같은 화면을 두 번 찍어 차이를 본다.

### 2회차 (11~20턴) · 디자인 · 전 저장소
- [ ] **빈 상태 · 실패 상태 문구** — "기록이 없습니다" 와 "못 물어봤습니다" 를 구별하나
      *이미 고친 자리:* DT `report.html`(`LOAD_FAIL`), `roster.html`(세 갈래 상태).
      *남은 자리:* exam 의 각 탭, KMChC `report.html`, DT 나머지 화면 전부.
      *끝난 기준:* 모든 읽기 자리가 **못 물어본 것 / 물어봤는데 없는 것**을 다르게 말한다.
- [ ] **느린 창구에서 무엇이 보이나** — 3초 지연을 걸고 화면을 찍는다
- [ ] **인쇄** — 성적표·상담지·해설지를 A4 로 뽑아 잘리는 자리를 본다

### 3회차 (21~30턴) · 내용 · exam + DT
- [ ] **표기 통일 전수** — 단위(`mol/L` vs `M`), 화학식 아래첨자, `°C` 서식, 화살표
      *재는 법:* `tools/dh_lint.py` 를 넓힌다. 이미 도는 검사다.
- [ ] **오탈자** — 사전이 아니라 **자기 데이터**로 잡는다: 한 번만 나오는 어절 중
      두 글자 이상 겹치는 짝을 찾아 사람에게 보여 준다(자동 수정 금지)
- [ ] **깨진 링크** — 자료·해설·문제지 주소가 실제로 열리나 (exam 은 도는 검사가 있다,
      DT `materials.json` 은 파일 존재만 본다)

# 2부 — 교육 (31~80턴)

여기부터는 **선생님 판단이 필요한 칸**이 섞인다. 그런 칸은 ⚖ 로 표시했고,
기계는 *후보를 뽑아 근거와 함께 보여 주는 데까지만* 한다.

### 4회차 (31~40턴) · 간격 반복
- [ ] **되풀이 개념이 언제 다시 나오나** — 지금은 "재시에 나온다" 뿐이고 간격 설계가 없다
      *재는 법:* 시트 기록으로, 한 개념을 틀린 뒤 다시 물을 때까지의 회차 수 분포
      *제안:* 1 → 3 → 7회차 간격. ⚖ 간격 값은 선생님이 정한다.
- [ ] **재시를 두 번 틀린 개념** — 지금은 아무 표시가 없다. 셸 개념 탭에서 위로 올린다.
- [ ] **선수 개념 드릴이 실제로 걸리나** — exam 에 `prereq-drill` 이 있다. DT 에는 없다.

### 5회차 (41~50턴) · 인출 연습
- [ ] **해설을 먼저 보여 주지 않는다** — 학생이 답을 떠올린 뒤 열게 한다(자기설명 유도)
      *지금:* 해설지는 문항과 해설이 같은 화면에 나란히 있다.
      ⚖ 인쇄본은 그대로 두고 화면본만 접을지 선생님이 정한다.
- [ ] **"왜 그렇게 골랐나" 한 줄** — OX 채점기에서 틀린 문항에만
      ⚖ 학생 부담이 늘어난다. 회차당 3문항으로 제한할지.

### 6회차 (51~60턴) · 오개념 교정
- [ ] **해설이 오답을 직접 반박하나** — 지금 해설은 "정답이 왜 맞나"를 말한다.
      틀린 학생이 필요한 것은 "**내 생각이 왜 틀렸나**" 다.
      *잰 값:* 지난 회차에 순환 해설 100건을 고쳤다. 남은 것은 **thin 39건**
      (`ch1_09`·`ch1_14`·`ch1_18` 에 몰려 있다) — ⚖ 선생님이 보류한 칸.
- [ ] **자주 같이 틀리는 개념 짝** — 상관을 재서 "이 둘을 헷갈리고 있다"를 짚는다
      *재는 법:* 시트 기록의 개념별 오답 벡터 상관. 상위 20짝을 선생님에게 보여 준다.

### 7회차 (61~70턴) · 인지 부하
- [ ] **한 화면에 몇 개를 묻나** — 성적표가 한 번에 던지는 숫자 개수를 센다
      *지금 DT 성적표:* 원점수·석차·백분위·다지기 단계·회복 점수·개념 목록·자료·재시 CTA
      *끝난 기준:* 첫 화면에 **셋 이하**, 나머지는 접는다. ⚖ 무엇을 셋으로 할지.
- [ ] **부모용과 학생용을 나눈다** — 지금은 한 장으로 둘 다 본다
      ⚖ 나눌지 / 한 장 안에서 접을지.

### 8회차 (71~80턴) · 전이
- [ ] **동형문제가 실제로 다른가** — 숫자만 바꾼 것과 맥락을 바꾼 것을 구별해 센다
- [ ] **재시 커버리지 유지 검사** — 99.8% 를 지키는 검사는 있다. 회차가 늘면 다시 잰다.

# 3부 — 행동경제학 (81~130턴)

⚠ **학부모·학생에게 나가는 글이다.** 여기 항목은 전부 ⚖ 다 — 기계는 문구 후보와
근거를 만들고, **나가는 글은 선생님이 고른다.**

### 9회차 (81~90턴) · 손실 회피 · 프레이밍
- [ ] **오답 수 vs 정답 수** — 지금 파이널은 "틀린 문항 12개", DT 는 "맞힌 개념"
      두 앱이 반대로 말한다. ⚖ 어느 쪽으로 모을지, 학생/부모별로 다르게 할지.
- [ ] **"3문항만 더" 는 이미 있다** — 파이널의 `장려상까지 N문항`. DT 에는 없다.
      *잴 것:* 그 문장이 붙은 성적표의 재시 실행률 vs 안 붙은 쪽. 표본이 모이면.

### 10회차 (91~100턴) · 기본값 · 진행 부여
- [ ] **재시 기본값** — 지금은 학생이 눌러야 시작한다. "예약해 둠"이 기본이면 실행률이 오른다.
      ⚖ 강제로 느껴질 수 있다. 예약만 걸고 취소를 쉽게 할지.
- [ ] **진행 막대를 0 에서 시작하지 않는다** — 이미 응시한 회차를 채워 둔 채로 보여 준다
      (endowed progress: 채워진 칸이 있으면 끝까지 갈 확률이 올라간다)
- [ ] **미룸(snooze) 기본 기간** — 지금 셸의 미룸은 기본값이 없다. ⚖ 3일 / 7일.

### 11회차 (101~110턴) · 실행 의도
- [ ] **"언제 할지" 를 적게 한다** — 재시 CTA 옆에 "오늘 밤 / 내일 / 주말" 세 칸
      (implementation intention: 시점을 적으면 실행률이 오른다)
      ⚖ 문구와 선택지.
- [ ] **약속한 시점에 알림** — 지금 셸에 nudge 가 있다(`NDG_SENT_DAYS=3`, `NDG_PEND_DAYS=7`).
      학생 쪽에는 없다. ⚖ 학생에게 직접 보낼지, 선생님을 거칠지.

### 12회차 (111~120턴) · 사회적 증거
- [ ] **"같은 반 N명 중 M명이 마쳤습니다"** — ⚖ 뒤처진 학생에게는 역효과다.
      *제안:* 앞선 쪽에만 보여 주지 말고, **자기 과거**와 비교한다("지난 회차보다 2개 더").
- [ ] **또래 정답률은 이미 있다** — `peer-rate` 검사가 지킨다. 문구만 다듬는다.

### 13회차 (121~130턴) · 되풀이되지 않는 말
- [ ] **문구 다양성 재검** — DT 는 openers 5 · chronic 3 · closers 6 으로 늘렸다.
      exam 파이널의 문자 문장도 같은 자로 잰다(`message-variety` 검사가 있다).
      *끝난 기준:* 같은 학생이 **연속 3회** 같은 문장을 받지 않는다.

# 4부 — 디자인 · 가독성 마무리 (131~170턴)

### 14회차 (131~140턴) · 한 팔레트
- [ ] **네 저장소가 한 팔레트를 쓴다** — 지금은 세 곳이 `--muted`·`--sub`·`--faint` 를

### 15회차 (141~150턴) · 휴대폰
- [ ] **머리 높이** — 셸은 163 → 118px 로 줄였다. 다른 화면은 안 쟀다.

### 16회차 (151~160턴) · 인쇄
- [ ] **성적표 A4 한 장** — 지금 DT 성적표는 몇 장으로 나오나 안 쟀다
- [ ] **상담지** — exam 에 있다(`printSheet`). DT 에는 없다.
- [ ] **해설지 인쇄가 viewport 추가로 안 바뀌었나** — `@page` 가 맡으므로 안 바뀌지만,
      128장을 한 번은 실제로 뽑아 봐야 한다

### 17회차 (161~170턴) · 속도

- [ ] **첫 화면까지 걸리는 시간** — 390px · 느린 3G 로 잰다. 기준선부터 만든다.
