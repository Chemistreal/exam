# 200턴 순차 개선안 — 네 앱 전부

> 대상: **exam**(파이널·통합 셸) · **DT** · **KMChC** · **minimalism**
> 축: **내용 · 디자인 · 교육 · 행동경제학 · 가독성**
> 이 문서는 읽는 글이 아니라 **체크리스트**다. 한 칸을 끝낼 때마다 표시하고,
> 잰 숫자를 그 자리에 적는다.

---

## 이 문서가 있는 이유

지난 작업에서 실제로 고쳐진 것은 **전부 재고 나서** 나왔다.

- 통합 셸의 흐린 글씨 `--muted` 3.52:1 (눈으로는 "좀 흐린가?")
- DT 해설지 127장에 `viewport` 없음 → 휴대폰에서 글씨가 **5.5px 로 보이고 있었다**
- DT 주기율표 원자량 **6.3px** — 시험 중에 보라고 만든 표다
- 재시가 학생이 틀린 개념의 **55.9%만** 묻고 있었다

넷 다 눈으로는 안 보였다. 그리고 넷 다, 재는 자를 만들자마자 30분 안에 나왔다.

### 원칙 넷

1. **재고 고친다.** 의견으로 고치면 다음 사람이 도로 되돌린다.
2. **잰 값은 검사로 박는다.** 안 박으면 6개월 뒤 원위치다.
3. **자가 거짓말을 하면 즉시 멈추고 자부터 고친다.** 잘못 재는 자는 안 재느니만
   못하다 — 사람이 경고를 무시하게 되고, 그러면 진짜가 와도 안 본다.
   (이 자는 이미 세 번 거짓말을 했다: `esc()` 쓴 자리를 잡음 / 문장 뒤쪽의 엉뚱한
   `.name` 을 잡음 / 어두운 화면에서 흰 글씨를 흰 바탕에 얹어 잼)
4. **화학 내용의 옳고 그름은 기계가 판단하지 않는다.** 그건 선생님이 본다.
   기계는 *사람이 판단할 필요가 없는 것*만 본다.

## 0회차 — 끝난 것 (자 만들기 · 전수 검수)

| 저장소 | 결함 있는 화면 | 결과 |
|---|---|---|
| exam | 207 / 261 | **0 / 261** |
| DT | 147 / 148 | **0 / 148** |
| KMChC | 7 / 7 | **0 / 7** |
| minimalism | 0 / 3 | 0 / 3 (걸린 3건은 자의 거짓말이었다) |

- 대비 미달 **245곳** → 0 · 11.5px 미만 글씨 **977줄** → 0 · `viewport` 없음 **128장** → 0
- 표 머리 `scope` **1,694곳** → 0 · `<h1>` 없는 화면 **146장** → 0
- `tools/audit_pages.py` 를 네 저장소 CI 에 등록 — 새 화면이 들어와도 재어진다
- 팔레트를 세 저장소가 같은 값으로 공유 (`--muted #6f6a5e`, `--sub #5F6D7C`, `--faint #626D7B`)
- ⚠ 이 자는 지금까지 **일곱 번 거짓말을 했다.** 매번 재는 방식을 고치고 다시 쟀다.
  잘못 재는 자는 안 재느니만 못하다. **자가 이상하다고 하면 코드보다 자를 먼저 본다.**

  | # | 무엇을 잘못 쟀나 | 어떻게 들켰나 |
  |---|---|---|
  | 1·2 | `esc()` 를 제대로 쓴 자리 · 문장 뒤쪽의 엉뚱한 `.name` | 참·거짓 예시로 확인 |
  | 3 | 어두운 화면의 흰 글씨를 흰 바탕에 얹어 잼(1.04:1) | 소스를 열어 봄 |
  | 4 | 브라우저 기본 초점 고리를 "없다" 고 함 | **화면을 찍어 봄** (`outline-style:auto` 는 width 가 0px) |
  | 5 | "불러오지 **못했습니다**" 를 못 잡음 | 화면을 찍어 봄 |
  | 6 | 만들어 넣는 주소를 깨진 링크로 잡음 | 앞토막만 잘려 온 것을 확인 |
  | 7 | 한국어 어절로 오탈자를 재어 후보 2,014개 | 목록을 눈으로 훑음 |
  | 8 | 화면을 두 번 띄워 창구 수를 두 배로 셈 | 잠금 풀려고 reload 한 것을 확인 |

  여덟 중 셋은 **화면을 실제로 찍어 보고서야** 알았다. 숫자만 보면 안 보인다.

  그리고 **잴 수 없는 것을 억지로 재지 않는 것**도 같은 원칙이다. 이번에 둘을
  포기했다 — 한국어 어절 오탈자(후보 2,014개가 전부 거짓), 동형문제 차이도
  (출처 기록이 0개다). 근거 없이 말하느니 못 잰다고 적는다.

### 0회차에서 딸려 나온 것

계획에 없었지만 재다가 걸린 것들이다 — 계획보다 **자가 먼저**라는 증거다.

- **CI 가 40분 멈춰 있었다.** `tests/offline.js` 가 세 번에 한 번 멈춘다.
  `python3 -m http.server` 는 한 번에 한 요청만 받아서, 서비스워커 설치와 화면
  요청이 서로를 기다린다. `serviceWorker.ready` 에는 시간 제한이 없어 영원히
  기다린다. 여러 줄로 받는 서버 + 파수꾼 300초. 이후 14번 연속 통과.
- **검사가 라벨 너비를 상수로 붙들고 있었다.** `if(l < 40)` 의 40 은 '보기'
  라벨 너비를 손으로 베낀 숫자다. 글씨를 키우자 **동작은 깨졌는데 검사는
  통과**했다. 줄의 실제 너비로 재도록 바꿨다.

# 1부 — 재는 자를 넓힌다 (1~30턴)

지금 자는 **글자·색·뼈대**만 본다. 사람이 판단할 필요 없는 것 중 아직 안 재는 것들.

### 1회차 (1~10턴) · 가독성 · 전 저장소
- [x] **키보드로 끝까지 갈 수 있나** — 아홉 화면에서 Tab 을 70번씩 눌러 쟀다.
      **고칠 것이 없었다.** 통합 셸의 줄(`.row`) 하나만 실제 결함이었고
      (아래 참조) 나머지는 브라우저 기본 고리가 또렷하다.
      ⚠ **자가 네 번째로 거짓말을 했다.** "명단 화면 단추 넷에 초점 표시가
      없다" 는 거짓이었다 — 브라우저 기본 고리는 `outline-style: auto` 라
      `outlineWidth` 가 `0px` 으로 읽힌다. 화면을 찍어 보고 알았다.
      **안 고친 것을 적어 둔다.**
- [x] **통합 셸의 줄에 초점 표시가 없었다** — `.row:focus-visible` 이 outline 을
      지우고 옅은 옥색 배경만 남겼다. 종이색과 **1.13:1** — 사실상 아무 표시도
      아니다. 놋쇠 테두리(3.02:1)를 돌려놓고 브라우저 검사로 못 박았다.
- [x] **낭독기가 읽을 수 있나** — 표 머리 `scope` **1,694곳**, `<h1>` 없는 화면
      **146장**을 고쳤다(exam 136장·DT 83장·KMChC 2장). 눈에 보이는 제목은 다
      있었고 태그만 `<div>`·`<span>`·`<h3>` 였다. 두 규칙 다 전수 검수에 넣었다.
      *이름 없는 단추 0 · 라벨 없는 입력칸 0 · `alt` 없는 그림 0* 은 이미 통과.
- [ ] **색만으로 말하는 자리** — 통과/미달을 색으로만 표시하면 색맹은 못 읽는다
      *재는 법:* 색상 필터를 씌우고 같은 화면을 두 번 찍어 차이를 본다.

### 2회차 (11~20턴) · 디자인 · 전 저장소
- [x] **빈 상태 · 실패 상태 문구** — 창구를 끊고 DT 아홉 화면을 열어 쟀다.
      대부분은 못 불러왔다고 제대로 말한다. 고친 곳 셋:
      `roster.html`(세 갈래 상태·저장 잠금) · `report.html`(`LOAD_FAIL`) ·
      `admin.html`(빈 배열로 덮던 것 → `null` + 붉은 배너 + 제외 저장 차단) ·
      `pending.html`(선생님이 할 수 없는 안내 → 다시 불러오기 단추).
      ⚠ 여기서도 자가 거짓말을 했다 — 실패 문구 정규식이 "불러오지 **못했습니다**"
      를 못 잡아, 미응시 현황이 아무 말도 안 하는 줄 알았다. 화면을 찍어 알았다.
      *남은 자리:* exam 의 각 탭(이미 `실패 사유를 남긴다` 등 검사가 있다),
      KMChC `report.html`.
      *끝난 기준:* 모든 읽기 자리가 **못 물어본 것 / 물어봤는데 없는 것**을 다르게 말한다.
- [ ] **느린 창구에서 무엇이 보이나** — 3초 지연을 걸고 화면을 찍는다
- [ ] **인쇄** — 성적표·상담지·해설지를 A4 로 뽑아 잘리는 자리를 본다

# 2부 — 교육 (31~80턴)

여기부터는 **선생님 판단이 필요한 칸**이 섞인다. 그런 칸은 ⚖ 로 표시했고,
기계는 *후보를 뽑아 근거와 함께 보여 주는 데까지만* 한다.

### 4회차 (31~40턴) · 간격 반복
- [ ] **되풀이 개념이 언제 다시 나오나** — 지금은 "재시에 나온다" 뿐이고 간격 설계가 없다
      *재는 법:* 시트 기록으로, 한 개념을 틀린 뒤 다시 물을 때까지의 회차 수 분포
      *제안:* 1 → 3 → 7회차 간격. ⚖ 간격 값은 선생님이 정한다.
- [x] **되풀이해 걸린 아이를 위로** — 표시(`3회차 걸림` 딱지)와 `되풀이만` 거르개는
      이미 있었다. 그런데 목록은 **최근 순**으로만 세워서, 세 회차 내리 걸린 아이가
      이번 주에 한 번 걸린 아이 아래로 내려갔다. **보충 자리는 위에서부터 찬다** —
      적어 놓고 아래에 두면 안 읽힌다. 되풀이 횟수를 첫 기준으로 올렸다.
      ⚠ 검사 짜임(fixture)이 되풀이 아이를 가장 최근으로도 만들어 놔서, 최근 순
      만으로도 통과하고 있었다. 그 아이를 **덜 최근**으로 바꿔야 이 규칙이 실제로
      갈린다 — 그렇게 고쳐서 검사가 뜻을 갖게 했다.
- [ ] **선수 개념 드릴이 실제로 걸리나** — exam 에 `prereq-drill` 이 있다. DT 에는 없다.

      *재는 법:* 시트 기록의 개념별 오답 벡터 상관. 상위 20짝을 선생님에게 보여 준다.

### 7회차 (61~70턴) · 인지 부하
- [ ] **한 화면에 몇 개를 묻나** — 성적표가 한 번에 던지는 숫자 개수를 센다
