# 집필 워크플로 대본

에이전트 여럿에게 집필·검증을 나눠 맡길 때 쓰는 대본이다.

임시 폴더에 두었더니 컨테이너가 재시작될 때마다 사라졌다(세 번). 재료를 만드는
법은 `tools/gen_chunks.py` 로 남겼고, 그 재료를 **어떤 순서로 누구에게 맡기는지**는
여기 남긴다. 둘이 함께 있어야 「같은 방식으로 다시 돌린다」가 사실이 된다.

| 대본 | 하는 일 | 재료 |
|---|---|---|
| `twinbank.js` | 동형문제 집필 → 적대적 반박 → 수리 | `twinsrc/` |
| `perchoice.js` | 선지별 오답 해설 집필 → 반박 → 수리 | `misrc/` |
| `lecmap.js` | 유형 → 개념강의 배선 → 반박 | `lecsrc/` |
| `cropread.js` | 크롭에서 지문·선지 옮김 → 대조 → 수리 | `cropsrc/` |
| `tonefix.js` | 반말·해요체를 평서체로 (뜻은 그대로) | 고칠 파일 목록 |
| `dedupe.js` | 회차를 넘나들며 겹친 동형문제 재집필 | 겹친 쌍 목록 |
| `thicken.js` | 많이 틀렸는데 얇은 해설 증보 → 반박 → 수리 | `thinsrc/` |

공통 뼈대는 셋이다.

1. **집필** — 원문을 읽고 쓴다.
2. **반박** — 다른 에이전트가 **처음부터 다시 풀어** 틀린 곳을 찾는다.
   통과시키는 것이 아니라 틀린 것을 찾는 것이 목적이라고 못박는다.
3. **수리** — 지적을 **직접 확인한 뒤** 고친다. 반박자가 틀렸으면 고치지 않고 적는다.

3단을 다 거치기 전의 조각은 답지·은행에 넣지 않는다. 실제로 반박 단계가 잡아낸 것들:
지문에 옆 문항의 정답이 새어 있던 자리, 리보솜 하나에 단백질 4.8×10⁵개가 붙는 설정,
「이 실수를 하면 이 값이 나온다」고 적어 놓고 실제로 계산하면 다른 값이 나오는 자리.

## `thicken.js` 가 왜 크롭을 열게 하나

증보 대상 240문항 가운데 **지문이 답지에 글로 있는 것은 열넷뿐**이다. 나머지는
`crops/<시험>/<번호>.png` 에만 있다. 그래서 집필자·반박자 **양쪽 모두**에게
그림을 Read 로 직접 열라고 시킨다. 안 그러면 옛 메모 한 줄을 부풀려 «그럴듯한
틀린 해설» 이 길게 나온다 — 짧은 채로 두는 것보다 나쁘다.

같은 이유로 「크롭이 흐려서 못 읽으면 그 문항은 건드리지 말고 적어라」를 규칙에
넣었다. 채우지 못한 자리는 비어 있는 편이 낫다.

⚠ **정답 키는 이 워크플로가 절대 안 고친다.** 이 회차들은 채점이 끝나 성적이
이미 나갔다. 답이 틀렸다고 판단되면 `reviewNote` 에 적어 선생님께 넘긴다.
