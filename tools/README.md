# 동형문제 재집필 파이프라인

## 왜 다시 만드는가

구 `donghyung` DB(schemaVersion 1)는 **동형문제가 아니었다.** 2400건 전부가
`sourceExamId`/`sourceQuestion` 을 달고 **다른 시험의 기존 문항을 개념 라벨로 매칭해
연결**한 것이었고, 해당 문항에서 파생 생성된 항목은 0건이었다.

- 매칭 수준: `exact_type` 1434(59.8%) / `exact_area` 947(39.5%) / 기타 19
- `concept` 필드는 **원 문항 값을 복사**해 넣은 라벨이라 항상 일치하는 것처럼 보였다.
  실제로는 `jmchc-3` 1번(돌턴의원자론)에 `hwol-2013` 14번(결합 길이)이 붙는 식.
- 원본 1417개를 2400 자리에 재사용(한 문항 최대 10회 중복).
- 도형·선택지 추출에 실패한 167건(7.0%)은 `(…렌더 누락)` 문구와 빈 선택지를
  학생에게 그대로 노출했다.

## 원칙

1. **기출 복제 금지.** 집필 입력에 원문 지문·선택지를 넣지 않는다. 각 문항의
   `개념 / 영역 / 학습 포인트 / 함정`만 전달하고, 그 개념을 묻는 **새로운 상황·수치의
   독자 문항**을 집필한다.
2. **화학적 정확성이 최우선.** 계산형은 집필자가 재계산하고, 별도 검수자가
   독립 검증한다. 틀린 화학은 없느니만 못하다.
3. **글자만으로 완결.** 그림·도표가 필요한 문항은 만들지 않는다.
4. 오답 3개는 원 문항의 함정과 **같은 종류의 오개념**을 유도해야 한다.
   덧붙여 **정답 번호를 1~4에 고르게 나눈다.** 이 지시를 넣기 전에 집필한
   jmchc-1 은 60문항 중 31개(52 %)가 ②번이었다. ②만 찍어도 절반을 맞히면
   오답노트가 진단 도구로서 값을 잃는다. `tools/dh_rebalance.py` 로 확인한다.
5. **고유명사로 지정된 개념은 대상 자체를 유지한다.** 오스왈트 공정·하버법·리비히
   장치처럼 개념 이름이 특정 공정·장치를 가리키면, 그 공정을 다른 공정으로 바꾸지
   말고 수치와 묻는 방식만 새로 설계한다. (jmchc-5 32번이 접촉법으로 바뀌어 재작성함)
6. **문헌값을 지어내지 않는다.** 실제 물질의 Ksp·Ka·표준 전위를 인용하면 문헌값과
   맞아야 한다. 원하는 함정 구조가 실제 물질과 맞지 않으면 물질명을 일반화한다
   (염 (가) MA형, 금속 M 등). (jmchc-12 22번이 Pb(OH)₂ Ksp를 1.2×10⁻¹⁵로 써서
   문헌값 ~1.4×10⁻²⁰과 어긋났고, 사실과 반대되는 결론을 가르쳐 일반화 재작성함)
7. **"A가 크면 B도 이렇다"는 서열 문항은 실제 측정값으로 확인한다.** 두 가지를 본다.
   - **방향이 뒤집히는가.** 이론이 옳아도 그 물질에서는 반대일 수 있다.
     (jmchc-13 48번이 결합성 σ에 전자를 채우면 결합이 짧아진다는 MO 논리를
     CN/CN⁻로 물었으나, CN의 해당 σ가 사실상 탄소 비공유 전자쌍이라 실측은
     CN 1.172 Å < CN⁻ 1.177 Å 로 반대였다. 같은 논리가 실측과 맞는
     N₂⁺(1.116 Å)/N₂(1.098 Å) 쌍으로 교체함)
   - **간격이 충분한가.** 방향이 맞아도 차이가 측정 오차 수준이면 변별력이 없다.
     (hwol-2023 16번의 NO₂⁻ 124 pm 대 NO₃⁻ 126 pm를 CO 113 / CO₂ 116 /
     CO₃²⁻ 129 / CH₃OH 143 pm 계열로 교체함)
8. **숨은 전제가 필요한 진술은 전제를 지문에 쓴다.** "Ea가 작으니 역반응이 더 빠르다"는
   앞자리 인자 A가 같아야 성립하고, "양쪽성 염의 pH ≈ (pK₁+pK₂)/2"는 C ≫ Ka₁일 때만
   성립한다. 전제 없이 물으면 정답이 유일하지 않다. (jmchc-14 30번에 "앞자리 인자 A는
   서로 같다고 본다"를 추가함)
9. **표기는 유니코드로 통일한다.** 아래첨자 H₂O·위첨자 10²³·전하 Cu²⁺·오비탈 2p⁶·
   Δ H·℃·×·→·⇌ 를 쓴다. `H2O`·`10^23`·`도씨`·`->` 같은 ASCII 표기는 같은 오답노트
   안에서 다른 문항과 어긋나 보인다. 이 원칙은 hwol-2014 를 고치면서 생겼으므로
   그 전에 집필된 jmchc 계열 412문항에는 ASCII 표기가 남아 있었고,
   `tools/dh_normalize.py` 로 일괄 정정했다.
   **일괄 정정 도구가 새 오류를 만든 적이 세 번 있다.** 셋 다 "화학식처럼 생겼으니
   화학식일 것"이라고 넘겨짚은 데서 나왔다.
   · `Cu2+` 의 2 를 원소 기호 뒤의 화학식 숫자로 읽어 `Cu₂+` 로 내렸다. 구리(Ⅱ)
     이온이 구리 원자 2개가 되었다. 숫자 뒤에 부호가 붙어 있으면 그것은 원자 수가
     아니라 전하다. 269군데를 고쳤다. 다만 `I₃⁻`(삼아이오딘화)처럼 아래첨자가 진짜
     원자 수인 이온이 있어 예외 목록을 둔다.
   · `10^1.77` 의 정수부만 올려 `10¹.77` 로 만들었다. 유니코드에 위첨자 소수점이
     없어서 소수 지수는 아예 올릴 수 없다. `10^(1.77)` 로 괄호에 넣는다.
   · 위첨자 문자 범위를 `[⁰-⁹]` 로 잡았는데 ¹²³ 은 U+00B9·U+00B2·U+00B3 이라
     이 범위 밖이다. 가장 흔한 세 숫자가 통째로 빠졌다. 낱낱이 적어야 한다.
   그리고 **화학식 뒤의 `−` 가 언제나 음전하는 아니다.** `C₁(CH₃−)`·`−CO−NH−` 의
   `−` 는 구조식의 결합선이고 `d(x²−y²)` 의 `−` 는 오비탈 이름 속 빼기다. 그래서
   맨 전하 규칙은 모양으로 넘겨짚지 않고 **실제 이온 목록에 있는 것만** 바꾼다.
10. **정답에 이르는 경로가 둘이면 안 된다.** 끓는점 서열을 물을 때 분자량 순서와
   답이 일치하면 극성을 몰라도 맞히므로 진단이 되지 않는다. 실제 물질명을 쓰면
   암기로 맞힐 수 있는 문항(CaTiO₃ 단위 세포 등)은 X/Y/Z로 일반화한다.
   (hwol-2019 21번을 분자량이 같은 아세톤·뷰테인 쌍으로 교체함)
11. **한 시험 안에서 같은 문항이 두 번 나오면 안 된다.** 파트를 나눠 병렬로
   집필하면 집필자가 상대 파트를 볼 수 없어, 같은 개념이 양쪽에 배정됐을 때
   사실상 같은 문항이 나온다. 병합 직후 `dh_dupe_scan.py` 로 훑는다.
   (donghyung-3의 2번·31번이 둘 다 등전자 이온 반지름 순서였고, 28번·39번이
   둘 다 콕으로 연결한 두 용기의 압력이었다. donghyung-2도 23번이 46번에
   통째로 들어 있었고 25번·35번이 같은 초기 속도 표였다)
   같은 개념이 원 시험에서 두세 번 나오는 경우도 있다. 그때는 문항을 지우지 말고
   **묻는 것을 서로 다르게** 만든다. jmchc-13의 17·18·19번은 셋 다 초기속도법인데,
   각각 속도식 판정 / 주어진 속도식으로 속도 예측 / 차수를 구하려면 어느 두 실험을
   비교해야 하는가로 갈랐다.
   `dh_dupe_scan.py` 는 지문의 겉모양을 재므로 "…에 대한 설명으로 옳은 것은?" 처럼
   상투구를 공유하는 문항은 내용이 전혀 달라도 0.4~0.5가 나온다. **반대 방향의 한계가
   더 중요하다. 이 도구는 베낀 문장은 잡지만 베낀 문제는 못 잡는다.**
   kmchc-2026-1-ilban 의 37번은 donghyung-3 19번과 수치까지 같은 중화 열량계
   문항인데(50.0 + 50.0 mL, 25.0 → 31.8 ℃, −56.8 kJ/mol) 표현이 달라 유사도가
   0.45 아래였다. 7·42·47번도 마찬가지였다. **전량 직접 검산할 때 눈으로 찾는 수밖에
   없다.** 도구는 놓친 것을 줄여 줄 뿐 대신해 주지 않는다.
   시험끼리도 같은 일이 일어난다(`--cross`). 시험도 서로를 못 보고 집필되므로 한
   개념에 교과서적 문항이 하나뿐이면 여러 시험이 같은 것을 쓴다. 오답노트는 시험별로
   열리므로 시험 안 중복만큼 급하지는 않지만, **수치까지 같은 것은 고친다.**
   (donghyung-4 의 4·5·23·33·37·40·17번이 donghyung-3·jmchc-7·hwol-2023 의
   문항과 수치까지 같아 교체했다)
   **한 시험이 한 단원에 몰려 있으면**(sanyeom-60 은 60문항 전부가 산·염기라
   pH 8회·완충용액 6회·평형상수 5회가 겹친다) 집필 지시에서 **문항 번호마다 각도를
   미리 배정**한다. pH 를 강산 정의 / 강염기 pOH / 약산 근사 / 초희석 / 희석 변화량 /
   강산 혼합 / 강산+강염기 / 온도별 중성 으로 나누는 식이다. 같은 개념을 일부러
   짝지어 대비시키는 것(51·54번의 약산·약염기 당량점, 59·60번의 산성·염기성 균형)은
   중복이 아니라 설계이므로 유사도가 높게 나와도 그대로 둔다.
   **뒤에 끝나는 파트에게는 먼저 끝난 파트의 파일을 읽게 한다.** kmchc-2025-1-simhwa
   에서 2파트 집필자가 42번을 반데르발스 B(T) = b − a/RT 로 잡았는데, 그때 이미
   나와 있던 1파트 15번이 같은 식으로 보일 온도를 구하는 문항이었다. 집필자가
   1파트 파일을 직접 읽어 보고 42번을 압축 인자 Z 로 갈아엎었다. `--draft` 는
   병합된 시험만 대조하므로 **아직 병합되지 않은 형제 파트는 잡지 못한다.**
   이 시험의 중복 14건(1파트 5 · 2파트 9)은 전부 집필자가 눈으로 찾은 것이고
   `--draft` 가 잡은 것은 0건이었다.

## 사용법

```bash
# 1) 집필 입력 생성 (원문 미포함)
python3 tools/dh_manifest.py <examId> [시작번호] [끝번호]

# 2) 집필 → 파트 JSON 저장 (문항번호 → 엔트리 맵)
#    30문항을 한 번에 쓰려다 멈추는 일이 있었다. 5~6문항씩 나눠 설계하고
#    중간 결과를 그때그때 누적 저장하도록 지시하면 안정적이다.

# 3) 파트 병합 → donghyung/<examId>.json (schemaVersion 2)
python3 tools/dh_merge.py <examId> part1.json part2.json ...

# 4) 구조 검증
python3 tools/dh_validate.py donghyung/<examId>.json

# 5) 시험 안 중복 문항 검사 (지문 3-그램 유사도 · 같은 concept 쌍은 항상 표시)
python3 tools/dh_dupe_scan.py <examId> [임계값]

# 5-1) 시험끼리 대조 (완료분 전체)
python3 tools/dh_dupe_scan.py --cross [임계값]

# 5-2) 집필 중인 파트를 완료분 전체와 대조 (병합 전에 집필자가 직접 돌린다)
python3 tools/dh_dupe_scan.py --draft <파트.json> 0.35

# 5-3) ASCII 표기 정규화 (먼저 인자 없이 돌려 바뀔 내용을 확인한다)
python3 tools/dh_normalize.py
python3 tools/dh_normalize.py --write

# 5-4) 정답 번호 편중 확인·재배치 (한 번호가 28 %를 넘으면 손본다)
python3 tools/dh_rebalance.py <examId>
python3 tools/dh_rebalance.py <examId> --write

# 6) 회귀 테스트 (신·구 스키마 모두 검사)
python3 tests/wrongbook-assets.py
```

`dh_merge.py` 는 번호 누락·중복을 막고, 기출 참조 필드
(`sourceExamId`·`sourceQuestion`·`matchLevel`·`image` 등)를 병합 단계에서 제거한다.
`dh_validate.py` 는 그 필드가 남아 있으면 실패시킨다.

## 표시 계층

`final.html` 은 두 스키마를 함께 지원한다.

- `origin: "authored"` → **동형문제 · 같은 개념으로 새로 만든 문제**
- 구 DB 항목 → **같은 개념 유형 문제** + 출처(시험명·문항 번호) 표기
- `dhUsable()` 가드가 빈 선택지·플레이스홀더 항목을 화면·Word 양쪽에서 숨긴다.

## 검수 원칙

집필은 병렬 에이전트가 맡고, **화학적 정확성은 전량 직접 검산**한다.
문항마다 다음을 확인한다.

1. 정답이 실제로 맞는가 (계산형은 재계산)
2. 오답 3개가 확실히 틀리는가 (복수 정답 불가)
3. 지문이 조건 부족으로 모호하지 않은가
4. 해설의 수치·논리가 정답과 일치하는가

`tools/dh_review.py <examId> [시작] [끝] [--full]` 로 검수용 압축 출력을 얻는다.

**donghyung-1~4 · sanyeom-60 · kmchc 9개(640문항)는 `misconception`(함정) 필드가
전부 비어 있다.** 원 문항이 무엇을 노렸는지 알 수 없으므로, 집필 시 concept·
learningPoint 로부터 그 개념의 대표적 오개념을 직접 설계해 오답을 구성한다.

**세부 주제를 배정할 때는 매니페스트의 영역 이름을 먼저 확인한다.** kmchc-2025-2-simhwa
27번을 화학평형으로 배정했는데 매니페스트는 산화환원이었다. 집필자가 매니페스트를
그대로 복사하되 두 요건을 모두 만족하는 문항(착이온 단계별 K 로 반쪽 전지 전위를
구하기)으로 처리해 살아났지만, 배정표를 만들 때 영역 이름을 옮겨 적는 단계에서
틀리면 메타데이터와 내용이 어긋난다.

**kmchc 계열은 여기서 한 단계 더 나쁘다.** `concept`·`area`·`learningPoint` 가
전부 같은 영역 이름 하나로 되어 있어(예: 50문항짜리 시험에 "산화환원" 이 9번,
"고체" 가 6번 반복된다) 집필 입력이 사실상 영역명뿐이다. 그 라벨만 주면 아홉 개의
비슷한 산화환원 문항이 나온다. 그래서 **집필 지시에서 문항 번호마다 세부 주제를
직접 배정한다.** 산화환원 9문항을 산화수 매기기 / 산화제·환원제 판별 / 산성 균형 /
염기성 균형 / 반응성 서열 / 표준 전위 / 전지 구성 / 전기 분해 / 부식 으로 나누는
식이다. 이 배정이 이 계열에서 가장 품이 많이 드는 일이자 품값을 하는 일이다.

원 DB의 `concept` 라벨에도 오타가 섞여 있었다(계싼·워자·생서엔탈피·빛엔어지·
에탈올). 화면에는 표시되지 않지만 재집필본마다 복사되므로 `answers/` 와
`donghyung/` 양쪽에서 정정했다. 후보 탐색은 `python3 tools/dh_concept_scan.py`.

### 같은 시험이 두 ID 로 들어와 있다

`answers/` 를 전수 대조하니 **세 쌍이 같은 시험**이었다. 해설·오개념·정답이 60문항
모두 글자 단위로 같고 `concept` 만 다르다.

| | |
|---|---|
| hwol-2018 | kmchc-2018 |
| hwol-2019 | kmchc-2019 (정답 58/60 일치) |
| hwol-2024 | kmchc-2024-1 |

앱은 41개 시험을 보여 주지만 서로 다른 시험은 38개다. 대조는 다음으로 한다.

```bash
python3 - <<'PY'
import json,glob
from pathlib import Path
d={}
for p in sorted(glob.glob("answers/*.json")):
    q=json.loads(Path(p).read_text(encoding="utf-8")); q=q.get("questions",q)
    d[Path(p).stem]=[(q[k].get("learningPoint"),q[k].get("answer")) for k in sorted(q,key=int)]
n=sorted(d)
for i,a in enumerate(n):
    for b in n[i+1:]:
        if len(d[a])==len(d[b]) and sum(x==y for x,y in zip(d[a],d[b]))>=len(d[a])*0.9:
            print(a,"≡",b)
PY
```

**중복 항목을 지울지는 제품 쪽 판단이므로 건드리지 않았다.** 대신 뒤에 재집필하는
쪽을 앞의 것과 **일부러 다르게** 집필한다. 그러면 항목이 남아 있어도 학생은 같은
시험에 대한 독립된 두 벌의 문제를 얻고, 나중에 지우더라도 잃는 것이 없다.
집필 지시에 짝이 되는 시험 ID 를 반드시 적어 대조하게 한다. kmchc-2024-1 에서는
집필자 둘이 각각 16건·9건을 이 대조로 잡아냈고, 그중 6건은 수치까지 같았다.

재집필이 남은 시험이 있는지는 다음으로 확인한다(지금은 빈 목록이 나온다).

```bash
python3 - <<'PY'
import json,glob
exams=json.loads(open('final.html',encoding='utf-8').read()
    .split("const FINAL_EXAMS=",1)[1].split(";\n",1)[0])
done={json.load(open(f,encoding='utf-8')).get('examId')
      for f in glob.glob('donghyung/*.json')
      if json.load(open(f,encoding='utf-8')).get('strategy')=='original-authored'}
print([e['id'] for e in exams if e['id'] not in done])
PY
```
