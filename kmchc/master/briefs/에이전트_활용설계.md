# 에이전트 활용 설계 — 독립성으로 품질을 높인다

**원칙: 에이전트는 속도가 아니라 독립성을 위해 쓴다.**

이 프로젝트의 구조적 약점은 감사14호가 이미 특정했다 — *"Opus 자기감사는 계산·경계·파서층은
무결하나 판정층에서 체계적으로 관대하다."* 그래서 selfaudit(기계 신호)을 도입했지만,
판단이 필요한 층은 여전히 저작자 자신이 맡아 왔다.

에이전트는 이 문제를 **구조적으로** 해결한다. 저작자가 "안 본 척"하는 것과
별도 컨텍스트의 검증자가 **실제로 모르는 것**은 다르다.

## 0. 파일럿 결과 — 설계의 근거

T12 P1(M01807~M01816) 10제에 대해 **내가 직접 층5를 수행한 뒤**,
같은 문항에 독립 에이전트 4종을 붙여 비교했다.

| 검증자 | 적발 |
|---|---|
| **나 (자기 층5)** | **1건** — M01814 오답 ③ 이 사실 진술이라 복수 정답 위험 |
| solver (F1·F5) | 정답 10/10 일치 + **어미 불일치 1건**(M01810 ③ 혼자 "~것이다") |
| defender (F2) | **2건** — M01807 ③ 음(−)변별 위험 · M01815 ① 부호 무관성 |
| factchecker (F3) | **✗ 3건 + 편집 오류 1건 + △ 7건** |
| student-sim | **죽은 선지 15/30개** 예측 + 저난도 구조 2건 |

**나는 1건, 에이전트는 8건 이상.** 그중 3건은 내가 직접 써 넣은 물리 오류였다.

### 내가 만들었던 오류 — 자기감사로는 끝내 못 잡았을 것들

1. **M01808** "밀 수 있으려면 질량이 있어야 하지 — 힘은 질량과 가속도의 곱이니까"
   → F=ma 는 *밀리는 쪽*의 식이다. 게다가 광자는 정지질량 0이면서 운동량 p=E/c 로
     복사압을 만든다. **'질량 없으면 운동량 없다'는 오개념을 심는 서술.**
2. **M01815** "(−)였다면 끌어당겼지 되밀지 못해"
   → 거짓. 러더퍼드 산란 단면적은 (Z₁Z₂e²)² 에 의존해 **부호와 무관**하고,
     인력 퍼텐셜도 동일한 후방 산란을 만든다(러더퍼드 1911 논문이 명시).
3. **실험의 역사적 귀속** — 바람개비는 크룩스(1879), 그림자는 히토르프·골트슈타인.
   톰슨(1897)의 고유 기여는 전기장 편향 성공과 비전하 측정이다.
4. **M01814 문장 중복** — 직전 수정 스크립트가 만든 버그. 내가 못 봤다.

교재도 71쪽에서 "F=ma, 음극선은 질량을 가진다"라고 적고 있다. **교재를 충실히 따랐다는 것이
사실 검증을 대신하지 못한다** — 이것이 층5가 필요한 이유의 실례다.

### 뜻밖의 교차 검증

student-sim 이 A~D 네 프로필로 예측한 평균 정답률 **60%** 가,
실측 코호트 앵커 **63%**(T12 43문항)와 거의 일치했다.
가상 응시가 난이도 예측의 대리 지표로 쓸 만하다는 첫 증거다.

## 0-2. ★2차 패스 — '조치 후 다시 돈다'가 실증됐다★

1차 지적을 조치해 33곳을 고친 뒤, 같은 4종을 **다시** 돌렸다.
결과가 규칙의 존재 이유를 그대로 보여 준다 — **1차 수정 자체가 새 결함을 만들어 넣었다.**

| 2차에서 나온 것 | 출처 |
|---|---|
| 해설 동어 반복 **2건**(M01808·M01811) — 1차 수정이 만든 것 | factchecker |
| 평문 은행에 마크다운 `**` **6건** — 1차 수정이 넣은 것. 학생에게 별표가 그대로 보인다 | 기계 재검사 |
| F2 음(−)변별 위험 **3건**(M01807 ③·M01816 ②·M01809 ①) — 1차에서 못 잡은 것 | defender |
| stem 이 정답을 낱말로 노출(M01807) — 화학 지식 없이 문장 대조만으로 풀림 | solver + student-sim |
| 죽은 선지 16개 · **C(부분 이해)=D(숙달) 응답 10/10 완전 일치** | student-sim |

> **⑪에서 조치했으면 ⑩부터 반드시 다시 돈다. 수정은 그 자체로 결함을 만든다.**

### 누적 실적 — 재순회는 매번 무언가를 찾아냈다

| 회차 | 조치 규모 | **그 조치가 만든 새 결함** |
|---|---|---|
| T12 P1 1차 | 33곳 | — |
| T12 P1 2차 | 63곳 | 해설 동어 반복 2건 · 평문 은행에 마크다운 6건 |
| T12 P2 1차 | 41곳 | — |
| T12 P2 2차 | 72곳 | **세트 내 정답 누출 1건** · 오답 풀이 수치 불일치 1건 · 본문 앞뒤 뒤집힘 1건 |

**두 번의 재순회에서 두 번 다 나왔다.** 특히 P2 의 누출은 내가 F2 를 고치려고 오답을
바꾸다가 만든 것이다 — M01817 오답에 "구멍 뚫은 (−)극"을 넣자 세트 안에서
'구멍 뚫은 (−)극 = 양극선'이 확정되고, **'양극선'이라는 낱말 자체가 (+)를 알려 주어**
바로 다음 문항 M01818 의 정답이 앞 문항에서 새어 나갔다.

한 문항만 보면 보이지 않는다. **세트로 놓고 봐야 보인다** — 그래서 검증은
문항 단위가 아니라 배치 단위로 돌려야 한다.

### 2차가 새로 알려 준 두 가지

**① 중재 규칙은 프롬프트에 미리 넣어야 한다.**
1차에서 student-sim 은 *참인* 진술을 오답으로 쓰라고 권했다(아래 §2). 2차에서는
"대체 선지가 확실히 거짓인지 스스로 점검하고 무엇이 거짓인지 밝히라"는 제약을
프롬프트에 넣었고, 제안 16건이 전부 거짓 근거를 달고 왔다.
**사후 판정만으로 막지 말고 프롬프트 단계에서 막는다.**

**①' 제약을 넣으면 실제로 걸러진다 — 두 번째 증거.**
T12 P2 2차에서 student-sim 은 제2정답이 될 제안 **세 건을 스스로 기각**했다.
'핵 속 양성자 2개 + 무거운 전자 2개'(전하·질량 동시 충족), '진동수 합이 같다'(E=hν 라 참),
'떼어내려면 에너지가 필요해서'(속박 상태의 정확한 서술). 1차에서 실제로 그런 제안이
하나 통과할 뻔했고, 그때 제약을 프롬프트에 넣었더니 다음 회차부터 자가 검열이 걸렸다.

**② C=D 일치율이 죽은 선지 수보다 나은 지표다.**
2차에서 B(오개념)는 10문항 전부 틀렸다 — 문항이 오개념을 정확히 저격한다는 뜻이라 좋다.
그런데 C 와 D 의 응답이 **10/10 완전히 같았다.** 상위권 변별이 전혀 일어나지 않는다.
B 를 저격하는 것만으로는 부족하고, **C 를 흔들 오답**을 따로 설계해야 한다.
자세한 것은 `briefs/가상응시_오답매력도_리포트.md`.

## 1. 검증 에이전트 4종 (배치마다 · 병렬)

`python3 master/agent_pipeline.py prep <lo> <hi>` 가 입력 파일과 프롬프트를 생성한다.

| 에이전트 | 담당 | 받는 것 | **못 보는 것** |
|---|---|---|---|
| **solver** | F1 정답 정확성 · F5 자족성 | stem + choices | 정답·근거·해설 전부 |
| **defender** | F2 복수 정답 위험 | 문항 + 정답 + 오답 | 해설·근거 |
| **factchecker** | F3 해설 진술 | 해설만 | — |
| **student-sim** | 오답 매력도 · 죽은 선지 | stem + choices | 정답·근거·해설 전부 |

### 독립성 보장 3원칙

1. **입력 파일에 필요 최소 정보만** — solver 와 student-sim 은 정답조차 모른다
2. **`kmchc/` 접근을 프롬프트에서 명시적 금지** — `master_bank.json` 에 답이 있다
3. **검증자끼리 결과를 공유하지 않는다** — 병렬로 띄우고 종합은 저작자가 한다

## 2. ★중재 규칙★ — 에이전트끼리 충돌한다

파일럿에서 실제로 충돌이 났다. **에이전트 결과를 무비판 수용하면 오히려 품질이 떨어진다.**

### 충돌 사례

student-sim 은 M01808 의 죽은 선지 ③ 을 **"음극선이 (−)전하를 띠고 있다는 것"** 으로
바꾸라고 제안했다. 학생이 실제로 끌릴 만한 오답이라는 근거였다.

그런데 이 진술은 **참이다**. defender 가 바로 그런 오답(그 자체로 사실인 진술)을
음(−)변별의 원인으로 지목했다. 두 에이전트의 조언이 정면으로 부딪힌다.

### 중재 원칙

> **오답은 '거짓이면서 매력적'이어야 한다. 둘 중 하나만 만족하면 실격이다.**

| 오답의 상태 | 판정 |
|---|---|
| 거짓 + 매력적 | ✅ 이상적 |
| 거짓 + 아무도 안 고름 | 죽은 선지 — 변별도를 깎는다 |
| **참 + 매력적** | **최악 — 음(−)변별.** 아는 학생일수록 틀린다 |
| 참 + 아무도 안 고름 | 무해하나 무용 |

따라서 **defender(F2)가 student-sim 보다 우선한다.** 매력도를 높이려다 참인 진술을
오답에 넣으면 안 된다. 매력적인 오답은 *거짓인 오개념* 중에서 찾아야 한다.

### 그 밖의 중재 지침

- **이 규칙을 student-sim 프롬프트에 미리 박아 둔다.** 2차 패스에서 확인했다 —
  제약을 넣으니 제안 16건이 전부 거짓 근거를 달고 왔다(1차에는 참인 제안이 섞여 있었다).
- **죽은 선지를 0으로 만드는 것이 목표가 아니다.** 실측상 1개(0.422)는 0개(0.446)와
  거의 차이가 없다. 무리한 교체로 F2 위험이나 배치 내 중복을 만드는 쪽이 훨씬 손해다.
- 판정이 갈리면 **근거를 보고 저작자가 판단**한다. 다수결이 아니다.
- 에이전트가 제시한 사실 주장(과학사·물리)은 **반드시 별도로 확인**한다.
  파일럿에서는 톰슨의 네온 동위원소(1913)와 러더퍼드 산란의 부호 무관성을 각각 확인했다.
- 에이전트가 "문제 없음"이라 해도 통과의 근거로 삼되 면죄부로 삼지 않는다.

## 3. 설계 단계 에이전트 (배치 전)

| 에이전트 | 역할 | 왜 |
|---|---|---|
| **textbook-miner** | 교재 쪽 판독 → 개념 목록 | 490쪽을 한 컨텍스트에 담을 수 없다. 쪽 범위를 나눠 병렬 판독 → 개념 대장 |
| **duplicate-hunter** | 후보 지식 ↔ 은행 의미 중복 탐색 | 기계 R1~R5 는 scenario·skill·계산 골격만 본다. **의미 중복은 못 잡는다** |
| **distractor-designer** | 오개념 기반 오답 후보 생성 | 위 중재 규칙(거짓 + 매력적)을 만족하는 후보를 여러 개 받아 고른다 |

`python3 master/agent_pipeline.py design '<테마>' <시작쪽> <끝쪽>` 이 세 프롬프트와
`theme_bank.md`(그 테마 기존 문항의 발문·정답 전량)를 생성한다. 교재 이미지 경로는
글롭으로 찾아 넣는다 — unzip 이 한글 파일명을 `#Uxxxx` 로 망가뜨려 두었기 때문이다.

`duplicate-hunter` 는 Explore 형(읽기 전용 탐색)이 적합하다 — 은행을 봐야 하므로
독립성 제약이 없다. 다만 은행 전체를 헤매게 두지 않고 테마 대조표를 쥐여 준다.
**판정 근거로 반드시 기존 문항 ID를 대게 한다.** ID 없는 지적은 채택하지 않는다.

`distractor-designer` 에게는 **C(부분 이해)를 겨냥하라고 명시**한다. §0-2 에서 드러난
상위권 변별 0 문제는 오답이 B(오개념)만 겨냥해서 생긴 것이다.

## 5. 배치당 표준 절차 (개정판)

기존 ①~⑫ 에 에이전트 단계를 끼워 넣는다.

```
①  안전 게이트(사전)              len 실측·ID 충돌
②  소재                          ★개념 대장에서 미사용 개념을 꺼냄★
②' 쌍대조                        기계 R1~R5 + ★duplicate-hunter 에이전트★
③  위치·길이순위 사전배분          ★설계 단계에서 함께★
④~⑦ 자수·expr·자체검증·안전게이트
⑧  병합
⑨  selfaudit
⑩  factcheck (F4·F6·F7 기계)
⑪  ★독립 에이전트 4종 병렬★       solver·defender·factchecker·student-sim
⑫  ★중재·조치★                  충돌 시 F2 우선. 사실 주장은 별도 확인
⑬  verified 기록 + 개념 대장 연결
⑭  master_gate 전수 + housekeeping
```

⑪에서 지적이 나오면 **조치 후 ⑩부터 다시** 돈다.

## 6. 비용과 판단

배치 10제당 검증 에이전트 4개. 파일럿 실측으로 에이전트당 약 3만 토큰, 1~3분.
남은 8,189제면 배치 819회 × 4 = 약 3,300 에이전트.

**턴수 제약이 없다는 전제이므로 비용은 판단 기준이 아니다.** 다만 다음은 지킨다.

- 검증 에이전트는 **반드시 병렬**로. 순차로 돌리면 시간만 4배가 되고 독립성 이득은 없다.
- 배치가 아닌 **테마 단위로 묶어** 돌리는 것이 효율적이다(에이전트 하나가 10~40제 처리).
- student-sim 은 매 배치보다 **마디 감사(48·88·128·164)에서** 돌리는 편이 낫다 —
  죽은 선지 교체는 배치 간 균형까지 봐야 하므로.

- **student-sim 은 실제 학생이 아니다.** 예측 정답률이 앵커와 맞은 것은 고무적이지만
  표본 하나다. 실제 응시(4기)를 대체하지 못하며, 그때까지의 대리 지표일 뿐이다.
- **에이전트도 틀린다.** 파일럿에서 student-sim 은 참인 진술을 오답으로 쓰라고 권했다.
  중재 규칙이 없으면 에이전트가 품질을 떨어뜨릴 수 있다.
- **금지가 강제는 아니다.** 프롬프트로 `kmchc/` 접근을 막지만 도구 수준의 차단은 아니다.
  에이전트 보고에 풀이 과정이 드러나는지로 독립성을 사후 확인한다.
- 층5가 통과해도 **사실이 보증되는 것은 아니다.** 검증의 밀도가 올라갈 뿐이다.
