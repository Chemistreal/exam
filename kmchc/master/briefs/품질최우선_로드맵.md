# 품질 최우선 로드맵 — 10,000제까지

목표는 10,000제 유지, 턴수는 제약 없음, **판단 기준은 오직 품질**.
남은 8,189제를 어떤 체제로 만들 것인가, 그리고 이미 만든 1,816제를 어떻게 할 것인가.

---

## 0. 진단 — 지금 검증되지 않고 있는 것

### ★가장 큰 구멍: 사실 검증 층이 아예 없다★

감사 35회의 층 구조를 전수 확인했다.

| 층 | 검사 | 감사 리포트 등장 |
|---|---|---|
| 층1 | 구조·자수·해설 형식·G6 | 21건 |
| 층2 | selfaudit 자기복제 | 22건 |
| 층3 | 테마 경계 침입 | 39건 |
| 층4 | 판례(중복·거울·보완값) | 24건 |
| **층5** | **화학적 사실이 맞는가** | **없음** |

'검산'은 4건뿐인데 그마저 `answer_expr` 산술 재계산이다. 곧 **정답이 화학적으로 옳은지,
오답이 확실히 틀렸는지, 해설의 진술이 사실인지는 한 번도 독립 검증된 적이 없다.**

규모로 보면:

- 문항 1,816제
- 명시적 주장(정답 근거 1 + 오답 근거 3) = **약 7,264건**
- 해설 총 **954,290자** — 그 안의 화학적 진술은 세지도 못한다
- 이 가운데 독립 검증을 거친 것 **0건**

10,000제로 가면 이 수치가 5.5배가 된다. **지금 검증 체계를 넣지 않으면
40,000건의 미검증 주장이 쌓인다.**

## 1. 최우선 — 감사 층5 '사실 검증' 신설

### 무엇을 검사하는가

| 코드 | 검사 | 방법 |
|---|---|---|
| **F1 정답 정확성** | 정답이 화학적으로 옳은가 | 독립 패스에서 문항만 보고 풀어 같은 답이 나오는지 |
| **F2 복수 정답 위험** | 오답 3개가 **확실히** 틀렸는가 | 각 오답을 "이것도 맞다고 우길 수 있는가"로 공격 |
| **F3 해설 진술** | 해설의 화학적 주장이 사실인가 | 문장 단위 점검, 특히 곁가지 설명 |
| **F4 수치 정확성** | 반감기·파장·상수 등 | 참조 상수표와 기계 대조 |
| **F5 자족성** | stem만으로 답이 유도되는가 | 교재 밖 지식이나 암묵 가정을 요구하지 않는지 |
| **F6 표기 정합** | 핵종·화학식·단위 표기 | 기계 검사(ᴬZX 파싱, 원자번호↔원소기호 대조) |

F2가 특히 중요하다. **부분적으로 옳은 오답은 죽은 선지보다 나쁘다** —
잘 아는 학생일수록 그 오답에 끌리므로 변별도가 음수가 된다.
실측에서 변별도 −0.026인 문항이 실제로 있었다.

### 왜 '독립 패스'여야 하는가

같은 맥락에서 이어 읽으면 자기 확증이 된다. 감사14호가 이미 실증한 문제다 —
"Opus 자기감사는 자기복제 판정층에서 체계적으로 관대"했고, 그래서 selfaudit이라는
기계 신호를 도입했다. 사실 검증도 같다. **저작 근거를 보지 않고 문항만 놓고 다시 푸는**
절차로 설계해야 한다.

### 기계로 할 수 있는 부분

`master/factcheck.py` 신설:
- `master/constants.json` — 반감기·파장·원자량·물리상수 참조표(출처 명기)
- 문항 텍스트에서 수치 주장을 추출해 참조표와 대조
- 핵종 표기 파싱 → 원소기호와 원자번호 일치 검사, A/Z 산술 일관성
- 단위 혼용 검사
- **현재 반감기 수치가 등장하는 곳만 51건** — 전부 저작자 기억에 의존 중

### 적용 범위

- **신규**: 배치 병합 직후 필수. 통과 못 하면 병합 취소
- **소급**: 기존 1,816제를 테마 단위로 순차 검증. T1부터 시작(가장 오래됐고 위험 구간이 몰려 있음)

## 2. 스키마 확장 — 지금 기록하지 않으면 영원히 잃는 것

```jsonc
{
  // 기존 22필드 유지
  "source_page": 71,                 // 교재 쪽수 → 커버리지 추적
  "objective": "실험 결과에서 성질을 추론",  // 출제 의도(무엇을 재는가)
  "prereq": ["전하의 인력·척력"],       // 선수 개념 → prereq-dag 연결
  "verified": {                      // 검증 이력
    "layer5": "F1~F6 통과",
    "at": "감사36",
    "by": "독립 패스"
  },
  "observed_p": null,                // 실제 응시 결과 자리(비워 둠)
  "observed_disc": null
}
```

`observed_p`는 지금 비워 두되 **자리를 만들어 두는 것**이 중요하다.
나중에 응시 데이터가 들어오면 곧바로 붙일 수 있다.

## 3. 교재 전체 판독 → 개념 대장 (소재 고갈의 근본 해법)

T11 후반에 "소재 고갈"로 폐기 36건이 났다. 원인은 **교재의 어느 개념이 남았는지
모르는 채로 소재를 짜냈기** 때문이다. T12부터는 순서를 뒤집는다.

1. 테마 착수 전에 **해당 쪽 전부 판독**(T12는 이미 70~75·80쪽 완료, 76~78 남음)
2. 교재의 개념을 **원자 단위로 쪼개 목록화** → `master/coverage/T12.json`
3. 각 개념에 문항 ID를 붙여 나감
4. **남은 개념 = 다음 배치 소재.** '고갈'이 아니라 '잔여 목록'이 된다
5. 164제를 채우고도 개념이 남으면 → 밀도를 높이고, 개념이 모자라면 →
   자료·종합·메타로 전환할 시점을 **미리** 안다

이 방식이면 배치마다 소재를 헤매지 않고, 폐기율도 떨어진다.
490쪽 전체 판독은 큰 작업이지만 **한 번 해 두면 남은 8,189제 전체에 쓰인다.**

## 4. 오답 설계 체계화

현재 type 분류는 proc 64.9%로 사실상 작동하지 않는다. 두 가지를 바꾼다.

**(1) 오개념 카탈로그 기반으로 전환**
저장소의 `misconception-catalog.html`을 은행과 연결해, 각 오답이 **문서화된 오개념**을
가리키게 한다. "틀린 진술"이 아니라 "학생이 실제로 저지르는 오류"라는 기준을
말이 아니라 구조로 강제한다.

**(2) 오답마다 '사고 경로' 필수 기재**
현재 `error` 필드는 결과만 적는다("반감기는 양과 무관"). 여기에
**어디서 어떻게 그렇게 생각하게 되는가**를 넣는다. 사고 경로를 못 쓰면
그 오답은 아무도 고르지 않는 죽은 선지라는 뜻이다 — 쓰는 행위 자체가 검사가 된다.

## 5. 추정을 측정으로 — 실제 응시 파이프라인

지금까지 난이도는 전부 추정이다. 테마 앵커까지는 왔지만 **문항별 p값은 실제로
학생이 풀어야만** 나온다. 저장소에 도구가 이미 다 있다.

1. 은행에서 시험지 구성(`test-blueprint`)
2. 응시 → 응답 수집
3. `item-analysis`로 문항별 정답률·변별도, `item-response-theory`로 IRT 모수
4. `calibration`으로 은행에 되먹임 → `observed_p`·`observed_disc` 채움
5. 죽은 선지·음수 변별도 문항 실측 확인 → 수정

이게 돌기 시작하면 **1~4번의 모든 추정이 측정으로 바뀐다.** 품질 관점에서
가장 근본적인 변화이므로, 규모가 작아도(한 테마 60문항이라도) 한 사이클을 돌려 보는 것이 좋다.

## 8. 실행 순서 — 왜 이 순서인가

**지금 도입하지 않으면 8,189제가 미검증으로 쌓인다.** 나중에 소급하려면
10,000제를 다시 봐야 하므로, 체계를 먼저 세우고 생산을 재개하는 것이 옳다.

### 1기 · 체계 구축 (생산 일시 중단)
1. 스키마 확장 + 기존 1,816제에 신규 필드 자리 부여
2. `factcheck.py` + `constants.json` 구축, 기계 검사 F4·F6 가동
3. 감사 층5 절차 문서화 — 독립 패스 규약
4. T12 교재 잔여 판독(76~78쪽) + T12 개념 대장 작성

### 2기 · 새 체제로 T12 완주
5. T12 P2~ 를 새 절차(⑪⑫ 포함)로 생산 — **첫 '완전 검증' 테마**
6. 감사36~39에 층5 포함
7. T12 마감문서에 새 체제의 효과를 실측으로 기록

### 3기 · 소급 정리 (T13 생산과 병행)
8. 위험 구간 184제 표본 점검 → 방침 결정
9. 사실 검증 소급을 T1부터 테마 단위로
10. 소급 감사 부채 119제 triage

### 4기 · 측정 도입
11. 완성 테마로 시험지 구성 → 응시 → IRT 되먹임
12. `observed_p` 채우기 → 추정 기반 규칙을 실측 기반으로 교체

### 5기 · 잔여 테마 완주
13. T13~T61 을 확립된 체제로 생산
14. 최종 전수 감사 + 앱 `full_bank` 동기화 + 10,000제 집계 기준 확정

## 9. 이 로드맵이 바꾸는 것 — 요약

지금 체제는 **"서로 겹치지 않고 형식이 갖춰진 문항"**을 보장한다.
바뀐 체제는 여기에 **"화학적으로 옳고, 오답이 진짜 오답이며, 교재를 빠짐없이 덮고,
난이도가 측정된 문항"**을 더한다.

가장 중요한 한 줄: **35회의 감사가 문항이 맞는지를 본 적이 없다.**
10,000제로 가기 전에 이것부터 고쳐야 한다.
